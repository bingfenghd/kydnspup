# 站长接入与首次检测

本流程使用 DNSPup 客户 API。本站管理员账号与 DNSPup 平台账号相互独立；本站不会代为注册、申请套餐、付款或自动发起检测。

## 1. 部署本站并创建管理员

按 [部署说明](deployment.md) 启动服务，在 `/admin` 设置本站管理员密码。公网访问管理端应使用 HTTPS；远程初始化还需部署时配置的初始化令牌。先保存站点名称、地址和联系方式。

## 2. 注册 DNSPup，申请试用或开通

前往 [DNSPup 注册](https://dnspup.com/user/register/)，已有账号则 [登录](https://dnspup.com/user/login/)。在 [用户中心 → API 密钥](https://dnspup.com/user/api-keys/) 点击「联系管理员」，说明用于自建测速站，申请试用或开通节点 API。

当前由 DNSPup 平台审核并签发凭据。试用是否获批、工具、节点、额度、有效期和费用，以平台实际授权为准。本站不代收节点服务费用，也不代替平台确认申请或支付状态。

## 3. 保存凭据和来源绑定

开通后，在 DNSPup API 密钥页面取得 `api_key` 和 `api_secret`；不要使用他人的账号或凭据。在本站「节点 API」分别填写 API Key、API Secret，并选择与平台一致的来源绑定：

- 固定 IP：授权部署服务器的公网出口 IP。本地预览使用的出口也必须已获授权。
- 域名签名：填写与平台授权一致的服务器域名。仅修改本站域名输入框不会替代平台授权。

本站服务端加密保存凭据；浏览器不直接携带客户凭据访问节点平台。不要将凭据加入截图、工单、Git 仓库或公开配置文件。保存后输入框清空；留空保留当前密钥。更换凭据或来源绑定会重新开始连接核验和首次检测记录，清除凭据会清除接入状态。

客户 API 地址为 `https://api.dnspup.com/v1`，详细参数见 [DNSPup 开发者文档](https://dnspup.com/api.html)。

## 4. 核验连接与授权

点击「测试已保存的连接」。该操作读取账户、节点和工具授权，不提交检测、不消耗检测额度。成功后，本站更新节点目录及账户信息，显示本次核验时间。核验结果表示该次请求的状态，不能保证未来一直可用。

失败时，查看页面提示以及「连接自检与诊断」，核对凭据、来源绑定、账户启用状态、有效期和服务连接。修正后再次点击测试连接。不要用反复提交真实检测代替连接核验。

「刷新本地自检」只读取本地配置和已有核验记录，不访问上游，也不会替你完成一次新的连接核验。

## 5. 手动完成首次真实检测

点击「打开本站工具」，自行选择一个已授权工具、目标和节点，再手动开始检测。建议先选单个节点做一次 Ping；随后按需要验证 TCPing、HTTP、DNS、Traceroute 和 MTR，以及 IPv6。实际提交按平台规则计量；不要将连续测试作为默认试用操作。

本站记录当前凭据第一次取得有效检测结果的时间。保存凭据、连接核验成功或仅收到任务完成状态都不能替代有效测量；取得一份有效结果也不表示所有节点成功。

异步任务创建成功后，检测中刷新同一工具页面会继续查询原任务；已保存上游编号的任务可在服务重启后恢复。原任务查询不会再次检测或扣检测额度。创建响应丢失而未获得编号时，不要连续点击重新检测，先查看 [任务诊断](task-diagnostics.md)。

在「调用记录」查看提交时间、请求编号、错误代码和结果摘要：

- **任务已返回**：接口响应已返回，不等同于每个节点都成功。
- **目标超时、节点不可用、检测失败、未返回**：按实际结果分别统计，不自动重试收费检测。
- **到达目标、未到达目标、目标地址未知**：用于路由检测；任务结束与到达目标是不同状态，目标地址未知时不推断已经到达。

首次检测结束后，在后台刷新概览、调用记录或本地自检，即可看到最新记录。

## 6. 查看额度、到期与续费

在「站点概览 → 连接与配额」查看当前套餐、月请求额度、已用量和有效期。上游当前单位为 API 请求次数；本站每日提交数用于访问保护，不是实际扣费账单。最终用量与计费以 DNSPup 账户为准。

需要续费、调整授权或咨询试用时，回到 [DNSPup API 密钥页面](https://dnspup.com/user/api-keys/) 联系管理员。平台处理后，重新测试连接以更新授权。本站不提供未经平台确认的付款成功或续费成功状态。

## 导出排障信息

「站点概览」「节点 API」「调用记录」均提供「导出脱敏诊断」。文件包含版本、本地自检状态、接入时间、调用编号、请求编号、错误代码和结果计数，不包含目标、节点名称或 IP、API 凭据及原始上游消息。导出不触发新的检测。

向 DNSPup 管理员反馈问题时，提供问题发生时间、操作步骤及该诊断文件。不要同时提交数据库、加密密钥、密码或完整服务器环境变量。

## 配置自己的广告

进入「站点运营 → 广告与链接」，展开对应位置，填写广告标题、图片地址和跳转地址，启用后点击「保存设置」，再刷新前台。图片和跳转地址使用 HTTP(S) URL；空跳转地址只展示素材，不跳转。

桌面保留页头 2 个横幅、检测框上方和下方各 6 个（2 + 3 + 1 排列）、正文前 2 个；手机独立配置页头 1 个、菜单 2 个、摘要后 2 个、结果后 2 个。未启用的广告不占位，不内置源站广告内容。旧配置默认广告用于兼容早期配置；设置对应的新位置后优先使用新位置，全部关闭新位置广告时不会重新显示旧广告。首页继续使用默认广告设置。
