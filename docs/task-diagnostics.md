# 本地任务查询与诊断

本文说明 KY DNSPup 的任务查询、数据保留和排障方式。异步调用的详细契约见 [平台适配与恢复](platform-job-adapter.md)。

## 请求与恢复

- 前台为每次检测生成请求编号，调用本地 `POST /api/probes` 时带 `X-Request-ID` 和 `Prefer: respond-async`。本站校验并占位后返回 `202`；只有占位成功的任务会调用一次 DNSPup 上游。
- `GET /api/probes/{本地编号}` 查询运行状态和结果，不调用新的上游检测。原来源可读取原任务，其他来源或不存在的编号统一 `404`；来源按可信代理配置解析，不信任随意传入的转发头。
- 浏览器 sessionStorage 只保存待完成的编号和原工具路径，不保存凭据或完整检测参数。检测中刷新同一路径会继续查询该任务，持续检测不会自动恢复后续收费轮次。网络错误后可以点击「找回原请求结果」。明确的参数/权限/限流拒绝不保留恢复入口。
- 已鉴权的 account 接口明确返回 `capabilities.asyncProbesV1=true` 时，使用平台异步创建与查询。保存上游 ID 后，刷新页面、内存缓存淘汰或本站重启都只 GET 原任务；平台结果保留 24 小时。同一本地编号作为平台幂等键，保留期内不重复建单或扣费。能力缺失时兼容旧同步接口，旧同步任务执行中重启仍为 `unknown`，不自动重发。
- 最多缓存 20 个结果，每个上游响应上限 4 MiB，本地内存缓存最长 10 分钟；内存上限约 80 MiB 加本地摘要开销。完整结果不落本地磁盘，但平台任务 ID 持久保存，缓存丢失后可查询平台恢复。调用记录保留 7 天，平台幂等记录保留 30 天，两者不代表完整结果保留时间。
- 原进度条使用平台实际 `completedNodes/totalNodes`，不按时间推算；完成节点包含失败或超时节点，不代表测量全部成功。恢复查询遇到限流时遵守平台 `Retry-After`，本站重启后仍保留等待时间。

## 状态含义

任务的 `completed` 只说明上游收集结束。节点 `partial / timeout / unavailable / failed` 独立统计，缺失节点单独计数；有 HTTP 响应不代表其状态码为成功。MTR/Traceroute 的测量结束、完整路由与终点应答不是一回事。

终点只有明确 IP 与有效跳点匹配才算取得应答；未返回终点 IP 且目标是域名时显示未知，不凭 `complete=true` 推断到达。未取得终点应答不等于业务访问失败，ICMP 丢包率也不代表业务流量丢包率。

## 管理端诊断

`GET /api/admin/diagnostics` 要求管理员登录，只读取本地状态，不请求上游。主动「测试已保存的连接」才读取 account/nodes/tools，记录核验时间；更换/删除凭据会重置核验与首次测量状态，旧请求不能回写新凭据的接入状态。

诊断导出只有版本、固定自检文案、时间、工具、请求编号、固定错误代码及数值摘要，不包含目标、节点 IP/名称、密钥或原始响应。管理端常规调用列表仍显示去除 URL 查询参数与片段后的目标；前台「导出 JSON」仍是完整检测结果，应区别于「脱敏诊断」。

## 节点能力

兼容可选 `capabilities.ipVersions / capabilities.tools / lastSeenAt`。缺少字段保持未知，继续交给上游执行前验证；明确不支持的协议或工具会在选择/提交时排除。它表示平台调度资格，不是任意目标都能测通的保证。
